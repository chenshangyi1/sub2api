# Sub2API 唯一源码基线与账号能力路由规格

## 目标

将 `D:\\CodexWorkspace\\projects\\sub2api-server` 固化为 Sub2API 主站唯一源码基线，并修复所有分组类型下的账号模型能力误选与非流式请求失败问题。

## 源码与发布边界

- 本地唯一源码基线是项目根目录，至少包含 `backend\\`、`frontend\\`、`Dockerfile`，并保留完整构建所需的 `assets\\`、`deploy\\`、`ops-panel\\`、`docs\\`、`openspec\\`、`skills\\`、`tools\\`。
- `work\\`、`outputs\\`、缓存、日志、备份包不属于源代码基线。
- 线上唯一构建树是 `/opt/sub2api/build_context`；未经确认不得覆盖、构建、重启或部署。
- 后续修改只发生在本地唯一基线；发布时从已验证提交生成快照同步线上。
- 尚未上线的旧工作树补丁不得自动合入基线。

## 模型能力策略

账号级能力状态分为 `unknown`、`fresh`、`stale`。

- `unknown`：账号从未成功同步过上游模型，仍可被调度，以保持现有账号可用性。
- `fresh`：账号成功同步过模型列表；请求模型经过账号映射后，只有在同步列表中存在时才可选择。
- `stale`：最近同步失败但仍有旧成功列表；继续使用旧列表并记录过期状态，不把账号放行成全模型。
- 上游明确返回模型不支持时，只对当前账号和最终上游模型建立短期负能力状态并触发换号，不永久封禁账号。

同步成功必须持久化账号级模型快照、同步时间、状态和来源，并刷新账号/调度器模型缓存。同步失败不得清除最后一次成功快照。

模型判断必须检查请求模型映射后的最终上游模型；无映射时使用请求模型。所有普通分组、fallback 分组、混合分组和 adaptive 分组复用同一个账号模型判断。

## 协议能力策略

入站协议字段和上游协议字段独立：

- `inbound_stream` 表示客户端是否要求流式响应。
- `upstream_stream` 表示实际发给上游的请求是否使用流式。

对于已知只支持流式的账号，`inbound_stream=false` 时允许网关内部使用 `upstream_stream=true`，完整收集 SSE 后生成标准非流式 JSON。纯文本、工具调用、usage、finish reason、response id 和模型字段必须保持正确；不支持安全合并的事件必须返回可诊断错误并触发换号。

对于已知原生支持非流式的账号，保持原生非流式路径。能力未知时保持兼容尝试并记录实际协议模式。

## 可观测性

请求日志至少区分：`requested_model`、`mapped_model`、`account_id`、`inbound_stream`、`upstream_stream`、`upstream_endpoint`、能力状态和换号原因。不得记录凭证。

## 验收标准

1. 已同步账号不会被选择处理其同步列表没有的模型；映射后的上游模型检查正确。
2. 未同步账号仍可参与所有分组类型的调度。
3. 同步失败保留最后成功快照并标记过期。
4. 账号能力过滤覆盖普通、fallback、混合和 adaptive 路径。
5. 客户端 `stream:false` 不会因上游账号 stream-only 而直接失败；标准非流响应保留文本、工具调用和 usage。
6. 原生非流上游行为不回归，流式路径不回归。
7. 自动化测试覆盖上述行为，且本地构建树与线上构建树的发布差异可追踪。
